## 1. 背景与目标 (Background & Goals)

### 1.1 背景
当前系统每天自动爬取 arXiv 与 OpenAlex 顶会/顶刊论文，并通过 LLM 对单篇论文进行基础结构化信息提取（TL;DR、动机、方法、遥感交叉等）。然而，科研人员在日常科研中面临从“单篇阅读”到“把握宏观前沿趋势、寻找创新 Idea、设计可验证实验”的巨大跨度。

### 1.2 目标 (Goals)
1. **学术导师角色定位**：将 AI 设定为遥感智能解译与计算机视觉领域资深学术导师/博导，以专业、严谨且前瞻的视角进行深度研判。
2. **纯粹基于原始论文数据**：不依赖词频统计或聚类等后分析，仅直接利用爬取的原始论文元数据（Title、Abstract、Authors、Categories）进行直接理解与宏观推演。
3. **高效分层上下文管理 (Context Management)**：解决几十上百篇单日论文及 7 天/30 天历史时序对比带来的 Token 膨胀问题，采用分层时序蒸馏方案。
4. **自动化流水线无缝集成**：在每日爬取去重完成后，自动触发导师研报生成并落库，实现无需人工干预的“爬取即生成”。
5. **3篇梯队化落地科研思路与实验设计**：输出高创新性、高可行性的具体科研方案，包含研究痛点、方法构想、数据集/Baseline 对齐与实验设计。
6. **极简聚焦的前端呈现 (`advisor.html`)**：界面设计干净专注，无多余冗杂图表，聚焦研报阅读、时序对比与实验方案一键复用。

### 1.3 非目标 (Non-Goals)
* 不引入复杂的图形化拖拽式工作流或繁重的外部分析图表。
* 不替换现有的单篇论文浏览与关键词统计页面，而是作为独立且互通的专属学术导师页面。

## 3. 详细设计与核心模块

### 3.1 上下文管理与时序蒸馏策略 (Context Window Management)

#### 问题分析：
单日论文通常为 20~100 篇（约 1 万 ~ 5 万字符），若叠加 7 天（~300 篇）和 30 天（~1500 篇）的全部 Abstract，Token 将达到数十万，导致费用剧增、延迟变长且容易出现模型注意力分散。

#### 解决方案：分层时序蒸馏 (Hierarchical Temporal Distillation)
1. **今日原始论文（Day Level）**：
   - 从 `data/{date}.jsonl` 直接读取原始数据。
   - 提取格式：
     ```text
     [Paper #{idx}] Title: {title} | Authors: {authors} | Categories: {categories}
     Abstract: {abstract}
     ```
2. **7 天演进上下文（Week Level）**：
   - 优先查询过去 7 天已入库的 `advisor_reports` 中提炼的 `key_takeaways`（每日技术热点与趋势演进总结，每篇约 150 字）。
   - 若无历史研报记录（如系统刚初始化），则降级为对过去 7 天论文库抽取 `Title + Categories` 紧凑列表。
3. **30 天宏观脉络上下文（Month Level）**：
   - 查询过去 30 天内每周的代表性趋势提炼或宏观点评。
4. **控制预算**：
   - 总输入 Prompt 严格控制在 4,000 ~ 8,000 Token 以内，确保 LLM 具备最高注意力和推理深度。

### 3.2 AI 导师分析引擎 (`ai/advisor.py`)

#### 核心职责：
独立可执行脚本与模块，支持命令行调用和被 FastAPI 模块调用。

#### Prompt 结构设计：
* **System Prompt**:
  > 你是遥感图像智能解译与计算机视觉领域的资深学术导师与顶会审稿人（Research Advisor）。你具备深厚的理论功底、敏锐的前沿洞察力与丰富的实验指导经验。
  > 你的当前科研关注主题是：`{topic}`（默认：“遥感图像的处理与信息提取（目标检测、语义分割等）”）。
  > 你需对输入的原始论文进行严格的学术研判，避免空泛总结，给出具有可操作性、突破性的前沿分析与实验方案。

* **Human Prompt 输入**：
  1. 研究主题设定：`{topic}`
  2. 分析目标日期：`{date}`
  3. 今日原始论文集（逐篇 Title、Authors、Categories、Abstract）
  4. 过去 7 天演进参考脉络
  5. 过去 30 天宏观趋势背景

* **期望输出规范（结构化 Markdown）**：
  1. **今日前沿速递与导师研判**
     * 核心技术演进（今日在 Backbone/模型机制/物理先验方面的新动向）
     * 突破性/高关注度论文深度点评（至少 2-3 篇）
     * 跨领域交叉启发（通用 CV/NLP 最新思想向遥感任务的迁移机遇）
  2. **时序演进对比（7天/30天动向）**
     * 7 天技术漂移（哪些方向正在升温，哪些方向进入红海/出现套路化）
     * 30 天宏观脉络总结与顶会审稿人偏好指引
  3. **3 篇落地科研思路与实验设计**
     * **思路 1【顶会理论/架构创新型】**（瞄准 CVPR/ICCV/TGRS）
     * **思路 2【高价值痛点/任务落地型】**（解决复杂场景、小目标、多尺度或弱监督痛点）
     * **思路 3【多模态/大模型跨界融合型】**（遥感视觉语言大模型、多源遥感对齐等）
     * 每个思路必须严格包含：
       - `【选题名称】`（中英文）
       - `【研究痛点与动机】`（现有文献瓶颈）
       - `【核心方法设计】`（模型架构草图逻辑、关键公式/机制、先验融合点）
       - `【推荐公开数据集与Baseline】`（如 DOTA、FAIR1M、LoveDA、WHU 等具体数据集与基线对比）
       - `【实验验证与消融方案】`（主实验指标、关键消融模块设计）
       - `【审稿人潜在质疑点与防守策略】`（预判审稿人可能攻击的弱点及应对）

### 3.3 数据库设计 (Database Schema)

在 `data/statistics.db` 中新建 `advisor_reports` 表：

```sql
CREATE TABLE IF NOT EXISTS advisor_reports (
    report_date TEXT PRIMARY KEY,
    topic TEXT NOT NULL,
    summary_takeaway TEXT,          -- 简短概要（供未来时序对比使用，约150字）
    report_markdown TEXT NOT NULL,  -- 完整研报 Markdown
    ideas_json TEXT,                -- 3个科研思路的结构化 JSON（便于前端快速解析和单独复制）
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS advisor_settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 3.4 后端 API 接口设计 (`server_modules/advisor.py`)

1. **`GET /api/advisor/dates`**
   * 鉴权：需要 Token
   * 返回：`{"dates": ["2026-08-08", "2026-08-07", ...]}`（已生成研报的日期列表）

2. **`GET /api/advisor/report?date=YYYY-MM-DD`**
   * 鉴权：需要 Token
   * 返回：指定日期的研报详情（若未生成返回 404 或指示前端生成）。
   * 响应体：
     ```json
     {
       "date": "2026-08-08",
       "topic": "遥感图像的处理与信息提取（目标检测、语义分割等）",
       "report_markdown": "# 今日遥感前沿...",
       "ideas": [
         {
           "id": 1,
           "type": "顶会理论创新型",
           "title": "...",
           "pain_point": "...",
           "method": "...",
           "experiment_plan": "..."
         }
       ],
       "created_at": "2026-08-08 05:00:00"
     }
     ```

3. **`POST /api/advisor/generate`**
   * 鉴权：需要 Token
   * 参数：`{"date": "YYYY-MM-DD", "topic": "可选自定义主题", "force": false}`
   * 行为：执行 AI 分析生成，保存至 SQLite 并返回最新研报。

4. **`GET /api/advisor/settings` 与 `POST /api/advisor/settings`**
   * 获取/更新用户配置的研究主题（默认：“遥感图像的处理与信息提取（目标检测、语义分割等）”）。

### 3.5 自动化流水线集成 (`run.sh`)

在 `run.sh` 现有流程后增加 **步骤4：自动生成学术导师研报**：

```bash
# 步骤4：自动生成学术导师研报 / Step 4: Academic Advisor Analysis
if [ "$PARTIAL_MODE" = "false" ]; then
    echo "步骤4：生成学术导师前沿分析与科研思路研报... / Step 4: Generating Academic Advisor Report..."
    python ai/advisor.py --date ${today}
    
    if [ $? -ne 0 ]; then
        echo "⚠️ 学术导师研报生成跳过或遇到警告，不影响主爬取数据"
    else
        echo "✅ 学术导师研报生成成功 / Academic Advisor report generated successfully"
    fi
fi
```

并在 `app/main.py` 的定期文件扫描与启动扫描中补充研报检查机制，确保即使历史离线数据也能在首次启动时被自动补全。

### 3.6 前端极简页面设计 (`advisor.html`, `css/advisor.css`, `js/advisor.js`)

#### 页面整体风格与交互：
* **视觉一致性**：沿用全局现代深色/浅色配色系统、Inter 字体与玻璃拟态卡片效果。
* **顶部导航**：
  * 返回首页按钮
  * 日期选择器（Flatpickr 快捷选择历史日期）
  * 导师主题标签徽章（点击可弹出微调弹窗）
  * “重新生成” 按钮（带 Loading 状态）
  * “导出/复制完整研报” 按钮
* **页面主体结构**：
  1. **标题区**：`🎓 AI 学术导师 · 前沿研判与科研灵感工坊`，附带日期与主题副标题。
  2. **板块一：今日前沿速递与导师研判 (Card 1)**
     - 优雅渲染 Markdown 内容、引用块、代码块与关键论文链接。
  3. **板块二：时序演进对比（7天/30天动向）(Card 2)**
     - 清晰的上升热点、饱和内卷方向、审稿人趋势解读。
  4. **板块三：3大落地科研思路工坊 (Card 3)**
     - 顶部提供 3 个 Tab/Card 切换：
       * 💡 选题 1：顶会理论创新
       * 🎯 选题 2：高价值场景落地
       * 🧩 选题 3：多模态跨界融合
     - 每个选题下方展示完整结构化实验设计，并配有独立的 **“📋 复制本篇实验设计”** 按钮。

## 4. 测试与验证方案 (Verification Plan)

### 4.1 单元测试 (`tests/test_advisor.py`)
1. **数据提取与上下文截断测试**：验证 `ai/advisor.py` 能够正确从 raw `.jsonl` 文件提取指定格式的论文，并且在超过 100 篇论文时执行智能优先级截断保护。
2. **时序摘要合成测试**：验证历史数据缺失时优雅降级，历史数据充足时能正确聚合过去的摘要。
3. **数据库 CRUD 测试**：验证 `advisor_reports` 表的读写、覆盖更新与查询。

### 4.2 API 接口测试
1. 验证 `/api/advisor/dates` 返回正确的有效日期列表。
2. 验证 `/api/advisor/report` 正常返回研报及 404 异常处理。
3. 验证 `/api/advisor/generate` 的鉴权与重新生成能力。

### 4.3 端到端运行验证
1. 运行 `python ai/advisor.py --date 2026-07-10` 验证现有本地测试数据的研报生成。
2. 启动服务并访问 `http://localhost:8000/advisor.html` 验证页面交互与一键复制功能。
