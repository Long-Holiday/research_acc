# 关键词共现网络优化设计

## 目标

修复关键词共现网络因跨日期、语言和分类错误关联导致的异常稠密问题，并通过强关系筛选和前端交互优化提升图表可读性。保持现有 `/api/stats/network` 接口返回结构不变，不修改数据库结构。

## 后端设计

文件：`server_modules/stats.py`

1. 共现配对必须在同一 `paper_id`、`paper_date`、`language` 和 `category` 范围内完成。
2. `All` 分类仍按日期和语言统计；具体分类查询时，两个关键词都必须属于当前分类。
3. 对候选边按共现次数进行强关系筛选：
   - 最低共现次数为 2；
   - 全局最多保留 180 条边；
   - 每个节点最多保留 12 条边；
   - 使用确定性的排序规则，优先共现次数，其次按关键词名称排序。
4. 删除筛选后没有有效边的节点，避免显示无关联孤立点。
5. 继续调用现有 `community_detection`，返回 `{nodes, links}`，边字段仍为 `source`、`target`、`value`。

## 前端设计

文件：`js/statistic.js`

1. 保留现有缩放、拖拽、点击节点查看论文和社区颜色。
2. 边宽和透明度同时反映共现强度，弱关系降低视觉权重。
3. 节点大小继续反映关键词频次；悬停节点时只突出其邻接节点、边和标签。
4. 每次重绘前清理旧 SVG、tooltip 和 D3 状态，避免重复加载或排除关键词后残留旧图形。
5. 网络为空或没有有效边时显示明确提示；正常网络显示节点数和边数摘要。
6. 排除关键词、分类切换和重复加载继续复用现有 API 和状态流程。

## 测试与验证

后端新增测试覆盖：

- 相同 `paper_id` 但不同日期、语言或分类的数据不会产生共现边；
- 共现次数低于 2 的边被过滤；
- 全局边数和单节点边数均受限制；
- 分类筛选不会混入其它分类的关键词；
- 空数据和单节点数据返回稳定结果。

前端验证包括 JavaScript 语法检查和现有测试套件，并手动检查空网络、单节点网络、重复加载及排除关键词后的重绘行为。

## 非目标

本次不引入 PMI、TF-IDF 等新的关联度模型，不改变关键词抽取逻辑，不迁移或重建现有数据库。
